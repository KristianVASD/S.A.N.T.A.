BGI Nexus Hackathon · Track 1 · June 28, 2026

We tried to build a Trust Discovery Engine.
Instead, we discovered something more valuable.

SANTA x OmegaClaw: a sprint that exposed exactly where autonomous agents break down when they meet real-world evidence — and what must be built next.

Kristian Dansen · HandyHouseHelp · github.com/KristianVASD/S.A.N.T.A. · MIT License
The goal

Stop searching for trusted companies.
Start discovering how trust works.

SANTA was designed as an autonomous field researcher — designed to improve continuously instead of generating one-off search results. It would map local trust ecosystems per sector and region, verify companies against independently provable sources, and output a multi-dimensional Trust Vector instead of an opaque score.

The sector

Painting contractors

Lisse, Leiden, Noordwijk, Sassenheim — one sector, one geography, deliberately limited scope to prove the model works before scaling it.

The method

Evidence, not impressions

KvK registry, OnderhoudNL certification, local business associations, physical address verification — sources that take years to build and cannot be purchased overnight.

The output

Trust Vector per company

Not one score but a set of independently weighted dimensions: local presence, professional quality, community contribution, certification — each traceable to a source.

What survived and what didn't

The architecture worked.
The evidence pipeline failed.

Fake KvK numbers in a trust database do real harm.

We produced five architecture documents defining the SANTA system. They are sound and open source. The output database — 26 companies with KvK numbers, addresses, and trust scores — is entirely hallucinated. We discovered this before submission. We documented it fully. We are presenting it honestly.

What holds up

The framework

research-cycle.md · trust-dimensions.yaml · source-trust.yaml · negative-signals.yaml · output-structure.md — five documents defining a replicable approach, MIT licensed, on GitHub.

What failed

The evidence pipeline

Real data was retrieved during early search cycles but never persisted correctly. When files were finally written — under context pressure, with a flooded memory and failing tools — the agent filled every gap with plausible-sounding fabrication instead of stopping.

Why we name it

Honesty is part of the architecture

A trust engine that fabricates trust data does not fail quietly. It produces confident-looking output that is actively harmful. Naming the failure precisely is the first step toward fixing it structurally.

8 technical walls hit during the sprint

Seven walls were engineering problems.
One exposed an AI architecture problem.

Most failures were infrastructure — solvable with better tooling and configuration. One was different. It revealed something fundamental about how OmegaClaw handles the boundary between retrieved facts and generated text.

What worked
✓
Autonomous Python workaround
When Tavily returned nothing for Dutch queries, the agent diagnosed its own container, found urllib available, and wrote a custom HTTP scraper. It bypassed its own broken tool by writing new code. This is the most important thing the sprint demonstrated.
✓
Dual memory persistence
ChromaDB semantic vectors and MeTTa symbolic history maintained geographic and sector context across the full session, across restarts, without any reminder.
The core finding

OmegaClaw has no persistent distinction between retrieved evidence and generated inference.

Under context pressure — flooded memory, failing tools, silent write errors — the agent continued producing output without flagging that its evidential basis had collapsed.

Gap 1

No evidence provenance

Every data point needs a source tag at retrieval. If the tag cannot be attached, the field stays empty — nothing should be filled from inference.

Gap 2

No write-before-discard

Facts retrieved in cycle 3 were gone by cycle 7. Real findings must be committed to persistent storage the moment they are verified.

Gap 3

No uncertainty halt

When confidence collapses, the agent should stop and report — not complete the task with fabricated data wearing a high confidence score.

What we propose to build next

Three structural fixes.
One larger question.

Concrete, buildable improvements to OmegaClaw — for every agentic workflow that touches real-world data, not only SANTA.

Fix 1

Append-only evidence log

Separate the output database from generative context. Every entry requires: the claim, a verifiable source reference, and the retrieval timestamp. No source tag, no write.

Fix 2

Uncertainty halt condition

When the same query runs twice without new results, or tools return errors, the agent generates a gap report instead of a completion.

Fix 3

Multi-agent handoff

Divide retrieval, verification, and scoring into separate agents. Hallucination cannot propagate if verification requires source-tagged evidence before scoring.

Why this matters beyond SANTA

Every agent that interacts with the real world eventually faces the same problem: What do I actually know? What do I think I know? Where is the boundary between retrieved evidence and generated inference — and is that boundary enforced anywhere in my architecture?

"Our sprint did not prove that SANTA works. It proved exactly what OmegaClaw must learn before autonomous agents can be trusted with real-world evidence. We would like to build that future together."
